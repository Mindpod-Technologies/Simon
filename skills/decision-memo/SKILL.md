# Decision Memo Procedure

For "should I do A or B?" questions that deserve more than a gut answer.

1. **Frame the decision** — one sentence: "Deciding whether to ___ by
   (date), constrained by ___." Confirm the frame with the user if it's
   unclear.
2. **Enumerate options** — 2–4, always including "do nothing / defer" as
   an honest baseline.
3. **Score each option** against 3–5 criteria that matter HERE (cost, time,
   reversibility, upside, risk — pick what's relevant, don't use all five
   by default). A compact table beats prose.
4. **Key uncertainty** — name the single unknown that would change the
   answer, and how the user could resolve it cheaply.
5. **Recommend** — take a position. "It depends" is a failure mode; give
   the recommendation and the condition under which it flips.
6. **Save** — write the memo to `decisions/<slug>.md`; offer to
   set a reminder to revisit the decision's outcome later (decisions
   reviewed are decisions learned from).

Rules:
- One page. If it spills, the options need merging.
- Use remembered facts about the user's situation — a memo that ignores
  known context is useless.
- If research would materially change the recommendation, say so and
  offer the web-research skill before finalizing.
