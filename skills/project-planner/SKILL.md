# Project Planner Procedure

Take "I need to launch X" to a real plan with dates.

1. **Pin the outcome** — restate the goal as a done-state ("the v1 site is
   live and taking signups"). If the goal is vague, ask the ONE question
   that matters most (usually: deadline?).
2. **Milestones** — break the path into 3–7 milestones, each verifiable
   ("copy approved", not "work on copy"). Sequence them and note
   dependencies.
3. **Tasks** — under each milestone, list the concrete tasks; estimate
   effort in hours/days. Flag the critical path (the chain that sets the
   total duration).
4. **Risks** — name the top 2–3 ways this plan fails and the early-warning
   sign of each.
5. **Schedule** — propose dates working backward from the deadline. Offer
   to create reminders or scheduled check-ins for each milestone — create
   them only on confirmation.
6. **Save** — write the plan to `projects/<slug>.md` with a
   checkbox list the user can keep updated; offer to revisit it in the
   weekly review.

Rules:
- Plans fit on one screen: if it needs a Gantt chart, the milestones are
  too granular.
- Ask before scheduling anything; never silently create reminders.
- Say explicitly which estimates are guesses.
